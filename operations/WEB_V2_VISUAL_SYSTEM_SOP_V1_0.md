---

# 1. PURPOSE

This SOP establishes the owner-approved visual baseline for Elevation Web V2. It defines how the company brand, homepage/storefront experience, vendor relationships, and hero imagery should be interpreted by future design and development workers.

The visual system must support the accepted technical architecture without collapsing responsibilities:

- **WEB V2** = public customer experience.
- **COMMERCE V2** = catalog, SKU, price, availability, checkout, payment, and order truth.
- **OPS V2** = internal catalog, vendors, orders, shipping, leads, analytics, and administration.

Visual implementation must never be used as a reason to recombine Web, Commerce, and Ops into one runtime.

## REFERENCE 04 — PRIMARY HERO LANDSCAPE / BACKGROUND ASSET BASELINE

**Owner description:** the additional long landscape image with **no words / no embedded marketing copy**.

**Repository asset path:** to be recorded when the owner-provided source image is imported into the Web V2 asset library. Do not invent a filename or substitute another image.

### Classification

**PRIMARY WEB V2 HERO LANDSCAPE / TEXT-FREE BACKGROUND BASELINE**

### Description

This reference is the long-format scenic hero image supplied by the Owner for use as a clean background/visual canvas rather than as a completed advertisement.

The intended treatment is a wide cinematic hero image that supports the Elevation visual language: premium off-grid power, rugged terrain, Hawaii/island or mountain/ocean energy context, and strong dark/blue atmospheric contrast suitable for white/cyan Web V2 interface copy.

The key distinguishing rule is:

# **THE SOURCE IMAGE CONTAINS NO EMBEDDED WORDS.**

The image should remain text-free at the asset level so Web V2 can render live HTML/CSS content above it.

### Control use

Use this reference for:

- primary homepage hero background;
- wide desktop hero treatment;
- responsive crop variants derived from the approved source;
- selected campaign/landing hero backgrounds where appropriate.

### Hero text rule

Do not bake homepage headline, body copy, CTA labels, navigation, pricing, vendor status, or product claims into the hero bitmap.

Hero copy must remain live web content so it can be:

- responsive;
- accessible;
- editable;
- searchable;
- translated if needed;
- changed without regenerating the image;
- tested independently from the artwork.

### Crop and focal-point rule

Preserve the important scenic/product focal area across desktop, tablet, and mobile crops. Avoid arbitrary center-cropping if it removes the intended visual subject. Responsive derivatives may be created from the approved source, but they remain derivatives of the same owner-approved hero asset.

Do not replace the approved hero with a generated approximation without Owner approval.

# 6. ASSET GOVERNANCE

Future workers must distinguish these asset classes:

### MASTER ASSET
Exact approved corporate identity asset. Preserve exactly.

### REFERENCE DESIGN
Approved visual direction that may be adapted while preserving intent.

### HERO BACKGROUND ASSET
Owner-approved text-free scenic/technical image intended to receive live web overlays. Preserve clean source; create responsive derivatives only from the approved source.

### VENDOR ASSET
Vendor-controlled logo/product material used only where rights and relationship allow.

### GENERATED MARKETING CREATIVE
Promotional creative that may combine approved imagery and messaging but does not replace the master corporate identity or authoritative product imagery.

Do not overwrite or recompress authoritative master assets unnecessarily.

# 7. WEB V2 IMPLEMENTATION CONTROLS

The first Web V2 shell should preserve the established Elevation appearance rather than introducing a new framework-driven visual identity.

Substantial changes to the following require Owner approval:

- master logo treatment;
- primary color system;
- homepage hero direction;
- main navigation hierarchy;
- customer CTA hierarchy;
- major vendor-brand presentation model;
- replacement of the approved primary hero image.

Normal responsive implementation, accessibility fixes, layout cleanup, and component adaptation do not require redefining the brand.
