Resolve current `main`; read the Renogy row on `CURRENT_WORK_BOARD.md`, `vendor-project-sources/RENOGY_PROJECT_SOURCE.md`, this workflow, `RENOGY_VENDOR_MASTER_SOP.md`, the Sales-First Scope and current Launch Batch.

Identify the last verified Renogy action and next executable Renogy action. If a prior worker/chat/branch was interrupted, resume only the unfinished action rather than rebuilding completed dealer/onboarding work.

Before doing generic source research, review the current sales-led priority list.

Current first-wave focus:

2. `RNG-CTRL-RVR40` — Rover Li 40A MPPT controller;

### 3 — PORTAL + SOURCE INTAKE

Use the Partner Portal and supplier-provided package first.

Recover or receive:

- MAP policy / price-control source;
- SKU/product catalog data;
- inventory/availability source;
- approved media/spec/manuals;
- dropship ordering/tracking process;
- warranty/RMA/returns process;
- account/integration contacts.

Do not ask Renogy to repeat information already present in its portal/package.

Update the Renogy Project Source when a material onboarding/readiness fact changes.

### 4 — SOURCE NORMALIZATION

For each candidate SKU establish:

**EXACT SKU/MODEL → VERIFIED PRODUCT FACTS → MAP/PRICE CONTROL → SELLABILITY SOURCE → APPROVED MEDIA → FULFILLMENT STATE → DIRECT-SITE CHANNEL → WARRANTY/RETURNS REFERENCE**

Keep protected dealer cost/private inventory evidence outside public Git.

A missing protected fact blocks only the affected activation/claim. It does not stop drafting, merchandising, staging or work on another SKU.

### 5 — BUILD / STAGE CUSTOMER-READY LISTINGS

Use the existing Elevation universal catalog/store systems and approved presentation.

For each launch candidate prepare, from verified sources:

- exact product identity/model/SKU;
- customer-friendly title;
- use case / problem solved;
- verified feature/spec block;
- compatibility notes;
- availability language;
- fulfillment facts;
- exact warranty language where verified, otherwise omit/hold the unsupported term;
- in-the-box facts where verified;
- 2–4 useful cross-sell/system relationships;
- category/tag/SEO staging.

The Project Operations Manager may prepare records directly from verified sources. Route code/integration work to the shared Developer only when code change is actually required.

A product may be safely prepared as a clearly non-public draft before every activation gate clears, but it does not become ACTIVE merely because a draft exists.

### 6 — MAP / CHANNEL / SELLABILITY QA

Before publication verify:

- exact SKU/model;
- current MAP/advertising-price rule;
- current sellability/source;
- exact delayed-order authorization if unavailable;
- approved media/product facts;
- normal Lower-48 fulfillment state;
- exact warranty statement where one will be published;
- ElevationUpScales.com as the authorized channel.

If one item cannot be verified, hold only that SKU/action and continue the next safe Renogy task.

### 7 — DIRECT-SITE PUBLICATION + UNIVERSAL CATALOG

Publish each verified Renogy SKU to the direct website as soon as its minimum safe publication set clears.

Do not wait for the full Renogy catalog.

After publication verify:

- universal store discovery/search/filter;
- product detail page;
- public price/product identity;
- truthful availability/backorder state;
- cart/checkout or correct assisted path;
- source/vendor identity retention;
- mobile/desktop functionality;
- intended public search discoverability over time.

Use `UNIVERSAL_CATALOG_VENDOR_INTEGRATION_ACCEPTANCE_BASELINE_2026-09-10.md` for shared completion criteria.

No marketplace publication without later written supplier authorization.

### 8 — FIRST REAL ORDER PROOF

Use:

**CUSTOMER ORDER → EXACT SKU REVERIFY → MAP/PRICE CHECK → RENOGY AVAILABILITY → PARTNER PORTAL PURCHASE → SUPPLIER ACCEPTANCE → TRACKING → CUSTOMER UPDATE → DELIVERY → ACTUALS / RECEIPT**

The absence of a first order is not a blocker to additional safe Renogy catalog work.

### 9 — WARRANTY / RETURNS PROOF

Route warranty claims through Renogy's Warranty Team and preserve supplier authorization requirements. Customer-facing promises must not exceed current written Renogy terms.

### 10 — SALES FEEDBACK + SCALE

After publication, use real Elevation evidence:

- product views;
- add-to-cart rate;
- checkout starts;
- completed orders;
- gross contribution after fulfillment;
- customer questions;
- returns/warranty friction;
- cross-sell attachment;
- stock/backorder reliability.

Prioritize products that produce customer interest, sales, contribution and useful system relationships. Deprioritize low-value/high-friction items unless strategically necessary.

### 11 — REFRESH / MATURITY

After proof:

- establish repeatable MAP/data/media/inventory refresh;
- expand verified catalog waves;
- improve system-builder/collection fit through authorized data/configuration work;
- retain only products that fit real Elevation demand and operating economics.

## Gate maturity

### Stage 1 — PROVING — CURRENT

Renogy is approved, but live catalog/source integration/first-order proof remains in PROVING.

Keep first-path verification for exact SKU, MAP, source/sellability, approved media, direct-site channel and first supplier order.

Protected source gaps gate affected activation only; they do not create blanket WAITING while safe catalog work remains.

### Stage 2 — CONTROLLED

After a verified source/update path, compliant live catalog and clean first order:

- do not recreate dealer application/W-9/approval/portal setup;
- routine Renogy direct-site catalog/order work uses targeted current SKU/MAP/sellability checks;
- source refresh and exceptions drive additional review.

### Stage 3 — MATURE / EXCEPTION-BASED

After repeatable clean source refresh/orders/returns handling, normal already-authorized Renogy work proceeds by default; management attention focuses on changed MAP/channel/source facts and material fulfillment/warranty exceptions.

If one SKU/source/order fails, reopen only that affected control unless evidence proves a broader Renogy process failure.

## Waiting behavior

While waiting on one Renogy protected/source fact, the project continues other Renogy-only work:

- next prioritized exact-SKU recon;
- launch-wave listing construction;
- non-public staging;
- comparison/compatibility/cross-sell preparation;
- category/tag/SEO preparation;
- approved-media organization;
- universal-catalog field mapping/QA;
- first-order receipt/process preparation;
- another clean product activation.

Return a project-level WAITING state only when **all remaining safe Renogy actions are genuinely dependent on unavailable external/protected evidence**.

External waiting does not authorize work in another project.

## Real gates

- unverified MAP/price control for activation;
- uncertain exact SKU/model;
- unverified current sellability/orderability;
- unapproved public media/product facts;
- unsupported destination/shipping path;
- unresolved exact warranty statement where one will be published;
- marketplace publication;
- payment/customer obligation;
- supplier authorization/compliance issue.

Do not preserve completed dealer application, W-9 correction, supplier approval, portal creation or no-MOQ verification as recurring gates.
