## Project outcome

Turn the already-approved Kingboss B2B relationship into a verified, controlled supplier/catalog/commerce lane without restarting qualification, inventing supplier terms, or displacing SOK's primary battery role without a defined product/commercial/logistics reason.

## Verified starting state

- Kingboss is an existing contact/relationship.
- B2B wholesale relationship is approved.
- Generic prospecting/requalification is closed.
- Current dependency is the supplier onboarding package/data.
- Operationalization still requires supplier-provided information around exact product identity, U.S. inventory/ship-from points, compliance support, and commercial fulfillment.
- SOK remains Elevation's primary battery relationship; Kingboss should be used where verified product, commercial, capacity, compliance or logistics value supports it.

This workflow intentionally does not invent MAP, pricing, inventory, channel, warranty, dropship, compliance-document or fulfillment terms that Kingboss has not yet supplied/verified.

## Unified project team

### Project Operations Manager

The Kingboss Project Operations Manager owns the Kingboss worktree and may directly execute routine, already-authorized Kingboss work such as:

- preparing and maintaining the Kingboss source/intake structure;
- organizing supplier files as they arrive;
- routine account/onboarding follow-through in the existing supplier relationship;
- public-safe project-state updates;
- catalog/schema preparation that does not require invented supplier facts;
- routing exact specialist/worker tasks after source data arrives;
- recording receipts and advancing the next Kingboss-only step.

The manager must not manufacture product/commercial terms simply to keep the lane busy while external data is pending.

### Project Specialist

The Kingboss Project Specialist owns:

- exact manufacturer SKU/model reconciliation;
- U.S. inventory / ship-from evidence verification;
- compliance/document-support verification;
- channel/MAP/price-rule verification when supplied;
- fulfillment/dropship/order-path verification;
- warranty/returns/support evidence;
- source-data normalization recommendations;
- EXACT / ESTIMATE / UNKNOWN classification;
- gap analysis against SOK and Elevation's actual needs.

### Shared workers

Catalog, Developer, Fulfillment, Compliance, Logistics or Communications workers enter the Kingboss project only through a bounded handoff after the prerequisite source facts for that task exist.

## Tailored operating sequence

### 1 — GIT / PROJECT SOURCE / WORKTREE PICKUP

Resolve current `main`; read the Kingboss row on `CURRENT_WORK_BOARD.md`, `vendor-project-sources/KINGBOSS_PROJECT_SOURCE.md`, this workflow, the Kingboss entry in `SUPPLIER_LEADS_LIVE_MAP.md`, and current Kingboss supplier correspondence/source package if available.

Identify the last verified Kingboss action and next executable Kingboss action. If a prior worker/chat/branch was interrupted, resume only the unfinished Kingboss action.

Do not restart B2B qualification.

### 2 — ONBOARDING PACKAGE INTAKE

Current state is WAITING ON SUPPLIER PACKAGE/DATA.

When information arrives, receive and classify:

- exact SKU/model/product catalog;
- U.S. inventory and ship-from locations;
- compliance/certification/document support;
- commercial pricing/MAP/advertising rules if any;
- authorized sales channels;
- order/dropship/fulfillment process;
- shipping/tracking process;
- warranty/returns/RMA/support process;
- approved product media/specifications;
- account/order contacts.

Do not request a second copy of information already supplied.

Update the Kingboss Project Source with the verified result of each material onboarding field.

### 3 — SOURCE VERIFICATION / GAP MAP

For each proposed product establish only verified states:

**EXACT PRODUCT → U.S. SOURCE / SHIP-FROM → COMPLIANCE SUPPORT → CHANNEL AUTHORIZATION → PRICE/MAP RULE → SELLABILITY → FULFILLMENT → WARRANTY/RETURNS → APPROVED MEDIA**

Classify missing items as UNKNOWN rather than guessing.

### 4 — ROLE AGAINST SOK

Evaluate Kingboss product lines for defined value such as:

- differentiated product/SKU;
- capacity or availability gap;
- commercial fit;
- logistics/ship-from advantage;
- compliance/document advantage;
- project-specific need.

Do not convert Kingboss approval into a generic replacement for SOK's primary battery role.

### 5 — CATALOG / DATA NORMALIZATION

Normalize verified Kingboss data into the existing Elevation catalog/source model. Preserve supplier identity and do not represent supplier inventory as Elevation physical On Hand.

The Project Operations Manager may prepare records directly when facts are verified. Use bounded Catalog/Developer work only when technical implementation is needed.

### 6 — PRICE / CHANNEL / COMPLIANCE QA

Before publication verify for each exact SKU:

- applicable MAP/advertising control or confirmed absence/structure;
- approved channel;
- current sellability/source;
- required product/compliance facts;
- approved media;
- order/fulfillment path.

A missing fact holds only that SKU/action.

### 7 — BUILD / STAGE / PUBLISH

Build only verified products and only on verified authorized channels. Do not publish merely because B2B approval exists.

### 8 — FIRST REAL ORDER PROOF

Once a verified sellable SKU is live:

**CUSTOMER ORDER → EXACT SKU / PRICE / SELLABILITY REVERIFY → KINGBOSS ORDER PLACEMENT → SUPPLIER ACCEPTANCE → TRACKING → CUSTOMER COMPLETION → ACTUALS / RECEIPT**

### 9 — SCALE / MAINTAIN

After first-order proof, establish a repeatable source/inventory/price/compliance refresh and expand only from verified demand and supplier performance.

## Worktree continuity + documentation

Material Kingboss state must be recoverable from the Work Board + Kingboss Project Source + this workflow/supplier map.

Document material changes such as:

- onboarding package arrival;
- portal/account setup;
- exact catalog/source/ship-from evidence;
- MAP/channel/order-path verification;
- compliance/media/warranty source availability;
- launch/first-order proof;
- real gate/maturity changes.

Do not create management noise while simply waiting for the same external package.

After COMPLETE / WAITING / VERIFYING / HOLD, automatically select the next safe unresolved Kingboss item. If none exists, return capacity upward rather than taking another project.

## Gate maturity

### Stage 1 — PROVING — CURRENT

Kingboss remains PROVING because the B2B relationship is approved but the operating source package and first sellable product/order path are not yet verified.

### Stage 2 — CONTROLLED

After source package verification, compliant SKU launch and one clean first order:

- do not recreate generic qualification;
- use the established source/MAP/channel/fulfillment refresh path for routine exact-SKU work;
- target verification to changed/risky fields.

### Stage 3 — MATURE / EXCEPTION-BASED

After repeatable clean source refresh and fulfillment, normal already-authorized Kingboss work proceeds by default; management focuses on changed source/compliance/channel facts and material order exceptions.

If one SKU/route/order fails, reopen only that affected control unless evidence proves a broader Kingboss source/process failure.

## Waiting behavior

While the onboarding package is external-waiting, the project may safely continue:

- source-folder/intake structure;
- existing correspondence reconciliation;
- generic internal field/schema preparation that contains no invented Kingboss facts;
- project scope/current-state maintenance;
- clear list of exact missing supplier inputs.

If no Kingboss action remains executable, record WAITING and return capacity upward. Do not self-assign another project.

## Real gates

Block only the affected action for:

- missing exact product identity;
- unverified U.S. inventory/ship-from source;
- missing required compliance support;
- unknown MAP/channel authorization;
- unverified sellability/order path;
- payment/customer obligation;
- material shipping/DG/compliance uncertainty.

Do not preserve generic qualification or internal manager review as recurring gates after the supplier operating path is proven.

## Owner gates

Return to Casey for:

- material inventory/bulk purchase;
- financing/credit obligation;
- exclusivity/contracts;
- material channel expansion;
- intentional policy exception;
- significant lithium/DG liability or new logistics commitment;
- other binding commercial/legal commitments.

## Close / proof condition

Kingboss reaches repeatable operating state when:

1. onboarding/source package is verified;
2. exact authorized sellable products are normalized;
3. price/channel/compliance/fulfillment controls are established;
4. verified products are launched on approved channel(s);
5. one real paid order completes supplier purchase through customer delivery;
6. refresh/warranty/returns routes are repeatable.
