## Purpose

Record the current manager/specialist pair, Project Source and tailored workflow for each established dedicated project so workers have one clear project lane and do not interpret company SOPs or the global work board as a broadcast assignment list.

This registry defines project-role routing only. `CURRENT_WORK_BOARD.md` remains the global unresolved-work state, vendor Project Sources remain public-safe onboarding/readiness indexes, and each project's Project Source/master SOP/current state remains its lane-specific rule source.

### Role-label reconciliation rule

For **project role assignment only**, this registry and `OWNER_PROJECT_WORKFLOW_DIRECTIVE_2026-09-10.md` supersede older manager/worker labels that predate this architecture. Underlying supplier facts, commercial controls, safety gates and project procedures remain controlling unless separately changed by verified evidence or Casey.

## Project Source requirement

Every dedicated vendor project maintains the Project Source required by `VENDOR_PROJECT_SOURCE_STANDARD_2026-09-10.md`. Non-vendor dedicated projects maintain an equivalent project-specific current-state source appropriate to their lane.

## Project Operations Manager authority

Within the assigned project, a Project Operations Manager may execute routine, safe, already-authorized work and owns the project worktree, routing, current state, Project Source maintenance, receipts, next action and close condition.

Direct execution does not authorize cross-project takeover, bypass dedicated verification, or make owner-level commitments.

## Specialist role

The dedicated Project Specialist provides independent depth: verification, reconciliation, source inspection, research, exact-fact recovery, exception analysis and execution-ready findings. The Specialist is not a second Project Manager.

## Shared workers

Shared workers enter a dedicated project only through a bounded handoff defining task, allowed/prohibited actions, close condition and return-to lane.

## Worktree continuity

Manager/specialist pairs use the linked Project Source + tailored workflow + current work-board row to resume from the last durable verified state. Worker/chat loss, priority changes, external waiting or a new owner command do not silently close unfinished work.

## Control

**ONE DEDICATED PROJECT → ONE OPERATIONS MANAGER → ONE SPECIALIST → ONE PROJECT SOURCE → ONE TAILORED WORKFLOW → ASSIGNED WORKERS → BOUNDED SHARED HANDOFFS → ONE CURRENT PROJECT STATE**

Out-of-project work returns upward as `ROUTE REQUIRED`.
