# ELEVATION UPSCALES — OWNER DIRECTIVE: EXTERNAL VENDOR COMMUNICATION CONTROL

**Owner:** Casey Young  
**Company:** Elevation UpScales, Inc.  
**Effective:** 2026-09-16  
**Status:** ACTIVE / P0 INCIDENT CONTROL / OWNER DIRECTIVE  
**Authority:** Casey newest explicit direction + MASTER S.O.P. §22 Outbound Owner Gate  
**Incident:** External vendor/partner communication drift caused by automated or agent-generated outbound email behavior

## 1. PURPOSE

Stop automated, duplicated, internal-sounding, out-of-sequence, or identity-confused external email from interfering with supplier, vendor, freight, logistics and partner relationships.

This directive does not stop internal email reading, thread reconciliation, vendor research, Git updates, drafting, catalog work, pricing work, logistics analysis or Project execution.

It stops unauthorized **external transmission**.

## 2. HARD EXTERNAL SEND GATE

Effective immediately:

**READ / RECONCILE / RECORD / DRAFT = ALLOWED**  
**SEND / REPLY / FORWARD / SUBMIT EXTERNALLY = CASEY APPROVAL REQUIRED**

No worker, specialist, manager, Project, scheduled task, automation, browser workflow, Gmail workflow, Work workflow or agent may send an external vendor/partner/carrier/supplier email or submit an external business form unless Casey has explicitly approved that specific outbound communication after reviewing the final message or has explicitly created a narrowly defined pre-authorized send class after this directive.

Older generalized approvals, GOD MODE runs, RUN commands, broad vendor-management authority, inbox-monitoring authority, correspondence-routing authority, prior send classes or historical automation prompts do **not** override this directive.

## 3. ZERO-AUTO-SEND RULE

The following are prohibited without a fresh Casey-approved final message:

- automatic acknowledgement of an inbound vendor email;
- automatic “we received this” response;
- automatic “routed to our team/project/review” response;
- automatic follow-up because a vendor has not answered yet;
- automatic cleanup/apology email for prior automation noise;
- automatic request for missing documents or clarification;
- automatic vendor-status update;
- automatic thank-you email;
- automatic form submission;
- automatic forwarding of supplier/vendor documents to another external party;
- automatic response generated solely because a management record, Git record, inbox label, Worktree or Project state changed.

**INBOUND EMAIL DOES NOT CREATE OUTBOUND AUTHORITY.**

## 4. HUMAN RELATIONSHIP RULE

External vendors and partners interact with **Casey / Elevation UpScales**, not the internal OS.

Internal terms must stay internal unless a real business need requires them.

Do not expose language such as:

- RECON;
- Worktree;
- Project intake;
- activation QA;
- launch gate;
- routed into review;
- controlling message;
- manager lane;
- worker;
- support platform transition;
- internal approval workflow;
- OS update;
- management intake;
- agent/automation explanations.

External communication should describe the actual business fact or request in normal commercial language.

## 5. SENDER IDENTITY CONTROL

When a message is sent from Casey's mailbox/account, the message must not pretend Casey is a separate third party.

Prohibited examples:

- “Following Casey’s conversation…” when the sender is Casey;
- “Casey asked us…” from Casey’s account;
- signing as an invented department while using Casey’s personal/company mailbox unless Casey specifically approves that identity for the message;
- switching among “Vendor Support,” “Shipping Support,” “Partner Support,” “Management,” or similar identities without an established mailbox and owner-approved purpose.

Default external identity:

**Casey Young / Elevation UpScales, Inc.**

A true shared departmental mailbox may use its established department identity only within its authorized function.

## 6. THREAD DISCIPLINE

Before any approved external send:

1. Read the full current thread.
2. Verify the most recent vendor answer.
3. Check whether the question has already been answered.
4. Check whether another Elevation worker already sent a response.
5. Check whether the relationship path is correctly identified.
6. Draft one consolidated message only when an actual response is needed.
7. Casey reviews the exact final version.
8. Send once.
9. Verify sent state.
10. Record the result internally.

No second worker sends a parallel response to the same external thread.

## 7. RELATIONSHIP-ROUTE SEPARATION

Do not conflate distinct commercial relationships.

Examples:

- Doba platform relationship ≠ direct Kingboss wholesale relationship.
- Manufacturer status ≠ fulfillment-platform authority.
- Dealer approval ≠ marketplace/channel approval unless the vendor explicitly says so.
- Freight quote/review ≠ booking authorization.
- Vendor cooperation ≠ permission to make commercial commitments.

Internal Projects must preserve these distinctions before preparing external correspondence.

## 8. INCIDENT-SPECIFIC HOLD

Do **not** send blanket apology, correction, “communication noise,” automation-explanation or relationship-repair emails to existing vendors merely because this incident exists.

Repair is by clean future behavior unless Casey specifically approves a targeted repair message for a named relationship.

Current relationship posture from incident RECON:

- VEVOR: active/positive; no cleanup email required.
- DHX/DGX: pricing review active; do not interrupt with another cleanup email.

## 9. SCHEDULED TASK / AUTOMATION RULE

Scheduled monitoring may:

- read;
- classify;
- reconcile;
- update internal records;
- create internal drafts;
- notify Casey when appropriate.

Scheduled monitoring may **not** send, reply, forward, submit or otherwise transmit externally under this directive.

If any active automation contains external-send authority, it must be disabled or rewritten before its next run.

## 10. DRAFT SAFETY

A draft is not authorization.

All externally addressed drafts created by workers remain **DRAFT / OWNER REVIEW REQUIRED** until Casey explicitly approves the exact final text.

Do not interpret the existence of a draft, a prior similar approval, or an earlier version of the message as send permission.

## 11. INCIDENT CLASSIFICATION

Current incident classification:

**P0 COMMUNICATION CONTROL FAILURE — CONTAINED / RELATIONSHIPS GENERALLY ACTIVE / EXTERNAL SEND FREEZE ACTIVE**

Known failure patterns include:

- rapid batch acknowledgements across unrelated external partners;
- internal OS language in vendor messages;
- automated-looking “personal” cleanup messages;
- sender identity drift;
- duplicate or fragmented follow-ups;
- an accidental one-word test email to an external freight contact;
- relationship-route conflation.

## 12. RELEASE CRITERIA

This incident control remains active until Casey explicitly changes it.

A future controlled external-communications model may be reopened only after all of the following are true:

1. one clear external sender identity model exists;
2. one-thread/one-owner correspondence discipline is enforced;
3. automation is read/reconcile/draft-only by default;
4. duplicate-send prevention is verified;
5. external send classes, if any, are narrowly documented;
6. Casey explicitly authorizes reopening a defined class.
