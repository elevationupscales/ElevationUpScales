# ELEVATION UPSCALES, INC.
## SOP — APPROVED BRAND ASSET CONTROL

**Owner:** Casey Young  
**Applies To:** Elevation UpScales-owned logos, hero graphics, wordmarks, approved campaign graphics, approved product/brand presentation assets, and future controlled visual assets  
**Operating model:** SOURCE → VERIFY → APPROVE → STORE → ASSIGN → DEPLOY → VERSION → RETIRE

## 1. PURPOSE

Elevation-owned approved brand assets are controlled operating assets. They must be handled with the same discipline used for approved SOK supplier assets: one canonical source, clear verification/approval state, controlled storage, assigned usage, and version history.

The website, store, checkout, documents, ads, and future workers must not recreate, redraw, restyle, substitute, or approximate an approved brand asset when the canonical approved asset is available.

## 2. CANONICAL ASSET RULE

For every approved brand asset, preserve:
- canonical file name;
- exact source file;
- owner approval state;
- intended use/placement;
- dimensions/file type where relevant;
- integrity hash when available;
- deployment path once assigned;
- replacement/supersession history.

A generated mockup, screenshot, derivative, compressed copy, or visually similar recreation is not a replacement for the approved source.

## 3. ACCESSIBILITY / FUTURE RETRIEVAL

Approved master assets must be placed in the persistent Elevation brand-asset library so future chats, workers, and development tasks can retrieve them without relying on an old conversation attachment.

Current approved persistent location pattern:

`/Elevation UpScales/Brand Assets/Approved/`

Reference or superseded material belongs under:

`/Elevation UpScales/Brand Assets/Reference/`

When a new approved asset is supplied, intake it into this structure before treating it as a reusable website/development asset.

## 4. WEBSITE / DEVELOPMENT RULE

Development must pull approved branding from the canonical asset source. Do not use AI-generated or substitute branding on production surfaces when an owner-approved asset exists.

Before changing a website brand asset:
1. identify the canonical approved source;
2. verify exact intended placement;
3. preserve aspect ratio and visual identity;
4. create only the technical derivatives required for delivery/performance;
5. do not alter artwork, wording, marks, colors, proportions, or composition unless Casey explicitly approves a derivative;
6. record the deployed path and version.

Technical optimization such as WebP conversion, responsive sizing, or compression is allowed only when the rendered branding remains visually faithful to the approved source.

An approved logo must be rendered from the image asset itself. Styled HTML text, CSS pseudo-elements, OCR-derived text, AI-generated lettering, or another approximation must not replace the approved logo when the source image is available.

## 6. APPROVED / REFERENCE LANE SEPARATION

Controlled assets must remain separated by use:

- **Approved Corporate / Lithium Shop:** current production-ready company and battery-retail identity assets.
- **Approved Apparel:** merch, embroidery, patches, garment/product graphics.
- **Reference / Black-Gold Legacy Sources:** older black/gold visual source material and backup concepts.
- **Reference / Marketing-Lifestyle:** campaign and lifestyle reference imagery.
- **Reference / Owner-Executive:** owner/executive source imagery.
- **Reference / Lithium Shop Variants:** useful lithium-brand variants that are not approved as final production marks.

Reference assets are retained for recovery and design context. They do not become production-authorized merely because they are stored.

## 7. FUTURE APPROVED ASSETS

Treat additional owner-approved Elevation assets exactly like supplier asset intake:

**01 SOURCE / ORIGINAL**  
Canonical uploaded source.

**02 VERIFIED ASSET DATA**  
File name, dimensions, type, hash, intended role, approval date.

**03 APPROVED USE / CHANNEL**  
Website hero, header, checkout, social, marketplace, document, apparel, etc.

**04 DEPLOYMENT / ACTIVE VERSION**  
Exact production path, derivative path where necessary, active version and verification.

**05 SUPERSEDED / RETIRED**  
Old versions remain identifiable but must not silently replace the current approved asset.

## 8. WORKER RULE

Any worker or developer receiving a branding task must first inspect the approved asset library/control record before creating new visuals.

If the requested approved asset cannot be retrieved, the task becomes **ASSET SOURCE REQUIRED** rather than permission to invent a replacement.

## 9. ACCEPTANCE

Brand-asset handling is correct when:
- the approved source is persistently retrievable;
- website/dev work uses the canonical asset;
- no generated substitute is presented as the official brand;
- technical derivatives preserve the approved identity;
- deployed versions can be traced back to the canonical source;
- reference variants remain clearly non-controlling;
- future assets follow the same controlled intake pattern.

**Controlling principle:**

**APPROVED BRAND ASSET = SOURCE OF TRUTH. DO NOT RECREATE WHAT HAS ALREADY BEEN APPROVED.**
