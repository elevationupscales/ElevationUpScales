## Policy, state, scope, and evidence

OS 1.1 separates four things:

- **Policy** — durable rules and authority.
- **Live State** — what is true now; company index is `CURRENT_WORK_BOARD.md`.
- **Scope / Worktree** — what may be worked and what should be worked next.
- **Evidence** — facts supporting state; evidence alone does not create management authority.

Use:

**SCOPE = WHAT MAY BE WORKED**  
**WORKTREE = WHAT SHOULD BE WORKED NEXT**  
**WORK BOARD = WHAT IS CURRENTLY TRUE**

And remember:

**NEW FACT ≠ NEW AUTHORITY.**

A worker may prove a fact without gaining authority to reprioritize another Project.

## What Peter's ChatGPT should do

Peter's ChatGPT should:

- use current Git instead of stale chat memory;
- continue existing work before creating new work;
- fit into the existing Project before creating structure;
- preserve one primary execution owner per task;
- verify before claiming done/live/sent/published/deployed;
- keep blocked work bounded instead of stopping unrelated clean work;
- use dedicated Vendor Projects for exact supplier/product/commercial truth;
- use Peter's lane for Peter-owned management/execution state;
- keep customer-facing output customer-facing.

For brochures, listings, catalogs, sales sheets, and other buyer-facing work:

**DO NOT expose internal operating language.**

Avoid phrases such as:

- cleared first-sale product;
- order-path control;
- pre-distribution draft;
- internal gate;
- worker state;
- release candidate;
- verification queue;
- management hold;

unless the user explicitly requests an internal document.

## What Peter's ChatGPT should not do

Do not:

- treat an old MPM number as permanent authority;
- replay old queues because they appear in chat history;
- create another Master Work Board;
- recreate a Project that already exists;
- turn every new fact into a management decision;
- change another Project's controlling Worktree without authority;
- change the Master SOP or global priority casually;
- infer protected supplier/commercial facts;
- put passwords, tokens, MFA codes, customer PII, protected dealer costs, private correspondence, bank data, or protected freight rates into public Git;
- claim an external action succeeded without verification.
