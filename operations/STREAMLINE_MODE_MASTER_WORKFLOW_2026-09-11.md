## Purpose

Turn current Elevation work into short, persistent, execution-first workflows without creating new authority, duplicate Projects, duplicate managers, or unnecessary gates.

STREAMLINE MODE means:

**USE THE EXISTING PROJECT → FIND THE LAST VERIFIED STATE → REMOVE AVOIDABLE FRICTION → HOLD ONLY THE BLOCKED ITEM → KEEP PROFITABLE WORK MOVING.**

It does not override protected legal, financial, security, production, MAP, channel, supplier, refund, booking, or owner-commitment gates.

## Universal RUN sequence under Streamline Mode

For every Git-aware manager/worker:

**GIT FIRST → PROJECT SOURCE / LANE SOP → CURRENT WORKTREE → ACTIVE-WORKER CHECK → LIVE PLATFORM / SOURCE CHECK → NEXT EXECUTABLE TASK → EXECUTE → VERIFY → RECORD MATERIAL DELTA → CONTINUE**

Do not perform a full RECON on every RUN. Trigger RECON only when state conflicts, evidence is stale/ambiguous, source files are unavailable, external result is unknown, or management truth has drifted.

## Streamline decision rule

At every blocker ask:

1. Does this block the whole Project or only one item?
2. Is the blocked fact actually required for the next action?
3. Can another clean SKU/order/task continue safely?
4. Is there an existing worker/Project already responsible?
5. Can the missing evidence be recovered from Git, Project files, Gmail, Drive, platform records or the original supplier source?

If only one item is blocked:

**MARK THE EXACT ITEM HOLD → PRESERVE THE REASON/TRIGGER → RETURN CAPACITY TO THE NEXT EXECUTABLE ITEM.**

## Management communication

Internal manager control does not use Gmail as the management source of truth.

Use:

**CASEY DIRECTION → GIT / MASTER WORKBOARD / MASTER MANAGEMENT COORDINATION WORKTREE → PROJECT WORKTREE → WORKER EXECUTION**

Gmail remains available for external communications and evidence/file recovery only, as defined in `GMAIL_EMAIL_NETWORK_SOP_V1_0.md` and `MANAGEMENT_COMMUNICATION_AND_FILE_RECOVERY_WORKFLOW_2026-09-11.md`.

## Source-file failure rule

Any missing, expired, inaccessible or wrong-version file triggers:

**FILE INCIDENT → REPORT TO MANAGER → RECON/OPERATIONS RECOVERY → VERIFY VERSION → RESTORE/REPOINT SOURCE → RESUME**

Do not substitute memory, a newer unrelated file, an older version, screenshots, guessed facts or public web data for the requested source unless management explicitly authorizes a source change.

Use `FILE_AVAILABILITY_INCIDENT_STANDARD_2026-09-11.md`.

## Worker behavior

Workers must:

- stay inside their assigned Project/lane;
- avoid duplicate work already owned by another ACTIVE worker;
- preserve exact blocked items;
- return unused capacity upward when their lane has no executable work;
- report source/file/access incidents immediately;
- use existing Project Source/Worktree instead of rebuilding context;
- record only material deltas in Git;
- avoid cluttering the Master Workboard with microtasks.

## Project Manager behavior

Project Managers must:

- keep one authoritative Project Source / CURRENT_WORKTREE;
- absorb worker receipts into Project truth;
- route only cross-Project deltas to Hybrid Management;
- suppress duplicate outreach/research;
- keep external waits from freezing internal executable work;
- verify that source files remain recoverable when a worker depends on them;
- return capacity upward when the Project has no executable task.

## Hybrid Management behavior

MPM / Company Project Manager / Company Operations Manager:

**KNOW → RECONCILE ONLY WHAT DRIFTED → PRIORITIZE BY PROFIT / CUSTOMER / RISK → ROUTE → VERIFY → UPDATE → CLOSE**

Hybrid Management should not take over a worker's lane simply because it is blocked. Route support to the blocked dependency and continue company-level sequencing.

## Stop conditions

Stop only the affected action for:

- unresolved customer money state;
- possible duplicate external action;
- unknown shipment/cancellation/refund result;
- security or credential risk;
- exact SKU/source ambiguity that affects fulfillment;
- MAP/channel violation risk;
- negative/unknown economics where promotion or purchase would create avoidable loss;
- binding owner-level commitments;
- missing critical source evidence that cannot yet be recovered.

## Streamline control phrase

**ONE PROJECT → ONE WORKTREE → ONE PRIMARY WORKER PER TASK → ONE VERIFIED SOURCE → HOLD ONLY THE BLOCKED ITEM → KEEP PROFITABLE WORK MOVING.**
