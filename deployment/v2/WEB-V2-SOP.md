# ARCHITECTURE BOUNDARY

Visual requirements do not alter the accepted technical architecture:

**WEB V2**  
Public customer experience.

**COMMERCE V2**  
Catalog, SKU, pricing, availability, checkout, payment, and order truth.

**OPS V2**  
Internal catalog, vendor, orders, shipping, leads, analytics, and administration.

Visual requirements must never cause Web, Commerce, and Ops responsibilities to collapse back into one runtime.

The release architecture remains separately controlled by `deployment/v2/README.md` and the exact-version GitHub Actions / Wrangler foundation.

# IMPLEMENTATION CONTROL

Before significant Web V2 visual implementation, a worker must verify:

1. the requested design aligns with Reference 01 customer/storefront direction;
2. any Elevation master logo use complies with Reference 02 protection rules;
3. any vendor claim or vendor creative complies with Reference 03 and is factually supported;
4. homepage hero/background treatment considers Reference 04 and keeps interface text/action elements live where practical;
5. the customer journey supports both **Shop** and **Start a Project**;
6. product/SKU/availability/payment truth remains owned by Commerce V2 rather than visual mockup content;
7. internal administration remains outside the public Web V2 runtime;
8. no visual task silently changes production, routes, domains, bindings, secrets, or Legacy Safe Prod.
