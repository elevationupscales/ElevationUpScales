# Overlap / Conflict Stop Prompt

Use this when two workers, candidates, or manager instructions may overlap.

---

Possible overlap or conflicting Management direction has been detected.

STOP new overlapping edits.

1. Read the Management Directory, Management README and Manager Feed Index.
2. Identify the accepted production baseline.
3. Identify every active WORK ID that touches the same system.
4. Identify each current branch/candidate/SHA.
5. Identify overlapping files, contracts, routes, business rules or customer flows.
6. Identify the newest Owner/Management direction.
7. Identify deployment custody for each work item.
8. Update the controlling Management feed with the conflict before more edits occur.
9. Assign one primary owner OR split into explicitly non-overlapping scopes.
10. Convert the other worker to review/support if needed.
11. Resume only when one controlling state is explicit.

Do not solve overlap by blindly merging or stacking both workers' changes.
Do not treat the newest branch as automatically authoritative.
Do not make Casey manually reconstruct which worker had the valid handoff.
